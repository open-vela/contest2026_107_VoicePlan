# 开发规划

## 9.2-9.3 环境准备

- 安装 AIoT-IDE。
- 更新 `aiot-core` 与 `aiot-emulator` 到 1.7.22+。
- 新建 `vela-miwear-watch-5.0(开发者大赛)` 模拟器。
- 打开 `quickapp/hello_quickapp/` 项目，确认能调试和打包。

验收：模拟器可启动，快应用首页能显示。

## 9.4-9.6 页面主流程

- 首页：显示项目名、心率/血氧/压力和当前计划入口。
- 统一目标：支持今日、本周、本月、本季度，不要求先选择生活类别。
- 计划设置：支持重要事项、提醒时间、天气场景和主动心情记录。
- 输入与生成：支持文字或 `system.record` 录音，先确认转写，再生成 AI/本地规则计划。
- 执行与复盘：展示今天任务、阶段进度、调整原因，支持完成、继续、调整和延期。
- 本地保存：计划生成、完成或延期后写入 `@system.storage`，重新打开可恢复。

验收：不接 AI 时，假数据能跑完整闭环。

## 9.7-9.9 AI 计划生成

- 定义结构化 JSON 输出。
- 编写 MiMo Prompt。
- 先用本地规则生成兜底计划。
- 快应用主链路通过 `@system.velaclaw` 调用设备端 AI Agent；本地预览服务提供 MiMo Chat Completions 联调和规则兜底。

验收：输入一句目标，得到可展示的结构化计划。

## 9.10-9.12 健康数据

- 接入 `service.health`。
- 读取心率、血氧、压力。
- 做三条简单规则：压力高降密度，心率高降运动强度，血氧低提醒休息。

验收：模拟器健康 Mock 数据能影响计划建议。

## 9.13-9.15 开发板展示

- 确认 SF32LB52-DevKit-LCD 串口可用。
- 验证屏幕、触摸、按键基础状态。
- 尝试部署快应用到板子；如受阻，保留模拟器完整 Demo，开发板展示硬件端原型。

验收：至少有模拟器完整演示和开发板硬件展示素材。

## 9.16-9.20 提交材料

- 录制 5 分钟内 Demo 视频。
- 写作品介绍文档。
- 整理源码、`release.rpk`、AI Coding 日志、Prompt/Skill 材料；补齐作品介绍文档和不超过 5 分钟的 Demo 视频。
- 最终压缩包按比赛命名规则提交。
